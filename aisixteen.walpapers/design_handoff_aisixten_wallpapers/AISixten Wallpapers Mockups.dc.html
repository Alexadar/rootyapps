Assumptions. The attached predecessor folder didn't sync to my workspace, so the create-flow rhythm is inferred from the brief (one calm popup, image-first presentation) rather than read from CreateItemPopup.swift. Name used as given ("AISixten"); I spelled "Wallpapers" conventionally in-UI. All controls follow one Liquid Glass recipe (see 1f) — glass floats over content, the image is never covered by an opaque panel. Every gray "Drop an image" tile is a slot you can drag a real generated wallpaper onto.
Surprise me — decision: it fills the field visibly. Generating directly would be one tap faster, but filling the field teaches what a good prompt looks like, keeps Create as the app's single generative act (one morph, one mental model), and makes re-rolling free before spending 20 s of compute. A second tap on the pill re-rolls the text.
Aspect ratio: the platform implies it — phone portrait, iPad 4:3, Mac per-display resolution. No picker on iPhone; iPad and Mac get a quiet override because their outputs genuinely vary. A picker on the phone would be a control 95% of users never need.
Honesty constraints kept. Progress is the real diffusion step count, never a fake bar. On iOS/iPadOS the app cannot set the wallpaper — the action is Save for Wallpaper and a short handoff (1c). On Mac, Set as Desktop actually finishes the job (1e). Nothing here requires a server; nothing the physics won't support — the emerging-image preview decodes intermediate latents every few steps, which is cheap.

6fWhat changes in the state machine
Gate. `checking → ready` gains `tuning(part, of)`, entered only on a cold compile cache; non-blocking (app usable behind it); ControlNet compiles inside it. Consent/download states stay dead code.
CreateModel. No new phases. `preparing` gains component-name labels from the existing `wakingFraction` events (6b). While the Gate is tuning, `canStart` is false and the Create button renders the tuning readout; a usable prompt + tuning-complete auto-starts only if the user tapped Create during tuning (explicit intent, queued — never on mere typing).
Enhance. Still owned by JobRunner, still orthogonal. New presentation state on whichever screen launched it: framed picture + 3×3 tile veil + "job" capsule (6c). `enhanceError` renders the same failure card as generation, with "Your wallpaper is untouched."
About. New sheet off Gallery header ⋯: model line, Acknowledgements, Advanced doorway, folder. Discharges the licence obligation on its face.
Resume. Same model, new clothes: chip on the bottom shelf, Discard demoted to long-press. Shelf priority: tuning > resume > toast.
Constraint flags. None violated. One tension worth naming: the queued-start in 6a begins Neural Engine work the user asked for earlier — it must be cancellable from the same capsule the moment it starts, and the tap that queued it must say so ("Starts when tuning finishes").
